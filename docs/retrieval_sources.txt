ROMA Web Search API - current retrieval source inventory
Generated for the current web_api codebase.

Important notes
---------------
This file lists sources that the current backend code can call or route to.
Actual availability depends on API keys, network access, provider rate limits,
and whether the route planner decides that a source is relevant for a request.

The current API default backend is skill_tree, so the usual runtime chain is:
API request
-> SkillTreeWebSearchToolkit route planning
-> web-search-innospark-tree/scripts/global_search_multi.py primary search
-> union-search-skill/scripts/cli/main.py enrichment when results/providers are insufficient
-> news-aggregator-skill/scripts/fetch_news.py or RSS fallback for news/trend/source-diversity cases
-> normalization, deduplication, provider-diversity rebalancing, final Markdown/JSON output


1. Primary sources in global_search_multi.py
-------------------------------------------
These are registered in:
script/skills/web-search-innospark-tree/scripts/global_search_multi.py

Default primary sources:
- tavily
- bilibili
- zhihu
- youtube
- duckduckgo

All registered primary source adapters:
- grok: xAI/Grok chat-completions search-style answer, requires GROK_API_KEY or XAI_API_KEY.
- tavily: Tavily Search API, requires TAVILY_API_KEY.
- academic_research: composite academic adapter inspired by academic-research-skills; queries scholar, OpenAlex, Crossref, and optionally Semantic Scholar.
- semantic_scholar: Semantic Scholar Academic Graph paper search; S2_API_KEY is optional but improves rate limits.
- crossref: Crossref Works API.
- openalex: OpenAlex Works API.
- scholar: scholarly search adapter; prefers Serper Scholar via SERPER_API_KEY, then falls back to DuckDuckGo site-restricted scholarly search.
- bilibili: Bilibili video search via TikHub, requires TIKHUB_TOKEN.
- zhihu: Zhihu search via union-search-skill zhihu adapter.
- youtube: YouTube Data API v3, requires YOUTUBE_API_KEY.
- duckduckgo: DuckDuckGo search via union-search-skill adapter.

8. Practical interpretation
---------------------------
For a normal broad web request, expect the system to start with Tavily,
Bilibili, Zhihu, YouTube, and DuckDuckGo, then enrich with MetaSo, Wikipedia,
RSS, and selected social/search platforms if coverage is weak.

For an academic request, expect Scholar/Serper Scholar, OpenAlex, Crossref,
Semantic Scholar, Tavily, DuckDuckGo, Google/Brave/Jina/MetaSo/Wikipedia/RSS,
plus academic authority-domain fallback.

For a policy request, expect Tavily, academic_research, DuckDuckGo, MetaSo,
Volcengine, Wikipedia, Zhihu, and official/institutional domain fallback, with
social/video platforms filtered more aggressively by default.

For a news/trend request, expect the general search chain plus news aggregator
and RSS fallback when provider diversity or result volume is insufficient.
